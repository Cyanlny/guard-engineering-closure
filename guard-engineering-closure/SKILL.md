# Guard Engineering Closure

Guard bounds closure; project-native authority and validators remain truth and acceptance.

Audit broadly; mutate only the smallest proven causal delta. New control surfaces require evidence that project-native mechanisms cannot satisfy acceptance.

Scientific edits/refactors/builds finish only through **real input → necessary scientific computation → real result → actual downstream consumption**. Preserve valid results; never substitute build success for this chain.

## Enter the lightest route

- Ordinary isolated, reversible, low-impact work stays native-only `LIGHT`: no Guard reference, state, or machine check.
- An explicitly requested simple `AGENTS.md` draft is also LIGHT: return one concise root-file draft from attributable facts, without writing, companion guides, V9, or invented commands, authority, or current state.
- For every other Guard closure, read [decision-loop.md](references/decision-loop.md) first. It alone defines mode, formal result, lifecycle arbitration, cycles, accounting, and the Closure Card.

## Load only a decision-changing risk

- [scope-authority-state.md](references/scope-authority-state.md): surfaces/reachability, identity invalidation, capabilities, authority, topology/concurrency, DAG.
- [verification-execution.md](references/verification-execution.md): scientific closure, capacity/cache pressure, compact I/O, incremental builds, final audit, proof/reuse, protected/preassembly gates.
- [rescue-rebase-handoff.md](references/rescue-rebase-handoff.md): recurrence, lost control, rebase, retirement, handoff.
- [crash-consistent-cutover.md](references/crash-consistent-cutover.md): authoritative replacement, durability, uncertain recovery.
- [v9-machine-contract.md](references/v9-machine-contract.md): V9 applicability/use/change, CLI, lineage, compatibility.
- [project-bootstrap.md](references/project-bootstrap.md): material instruction hierarchy/guide/capacity/root/precedence work or any instruction-file write; not the simple draft above.

References are conditional, not a checklist. Never guess legacy paths.

## Keep machine and project proof separate

Read the V9 contract before any machine check. Risk, complexity, or Git alone is insufficient; run V9 only when the current legal action needs an attributable enforced predicate. Machine no-veto never grants authority or project acceptance.
