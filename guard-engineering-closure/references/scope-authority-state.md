# Scope, Authority, and State

## Freeze three surfaces

- **Observation surface**: attributable, authorized reads that find authority, state, consumers, and validators.
- **Effect surface**: objects, locations, people, or external state the current legal routes may affect.
- **Verification surface**: subjects and boundaries whose evidence decides acceptance.

The **Mutation slice** is the already-authorized subset of Effect that the chosen action will actually change, not a fourth surface. Freeze all three surfaces and this slice after a read-only root trace. Bound Effect through the **minimum causally reachable frontier** to the first stable contract, including indirect consumers/effects. Classify protected core, required frontier, and adjacent deferral. If incomplete, enumerate consumers once and propose one consolidated rebase; never place an unauthorized consumer in Mutation.

## Use project-native terms

| Domain | Authority/generation | Frontier | Validator |
|---|---|---|---|
| Code/config | repo, revision, symbol/config | callers, interfaces, runtime | diff, test, build/service |
| Data/research | dataset, model, protocol/cohort | transforms, endpoints, figures/claims | schema/QC, held-out/scientific review |
| Document/sheet | revision, section/range/formula | references, pages, charts/exports | content, calculation, link/render |
| Artifact/migration | manifest, digest, schema generation | consumers, compatibility, rollback | digest, rehearsal, compatibility |
| Human/external | approval, request, transaction/lease | authorized effect, acknowledgment | authority plus terminal provider/project state |

Do not impose Git or a Guard/P0–S3 schema on another domain.

## Bind identity axes and dependencies

Use only decision-changing native axes: policy/instruction; subject/payload; operation; topology/targets; authority/admission; validator/evidence. These categories are neither schema nor closure keys.

For each axis cite its source and dependents; invalidate dependents only. Full-digest authority invalidates on any bound-byte change. Future-instruction changes alone do not reset payload, operation, or V9 lineage.

Logical membership does not require physical copies. Sharing requires content identity and scientific-context equivalence; never merge independent random repetitions, splits, or mutable state. New source installation alone does not invalidate healthy pinned-generation work: establish changed loaded dependencies/scientific contracts first. Preserve reusable scientific results separately from replaced implementations.

Reclamation requires native cache eligibility, not cache/tmp naming: protect unique science, required inputs/checkpoints, retention evidence, and live/pinned/unknown/dirty/concurrently changing objects under retirement rules. Authorized, validated native checkpoint/resume may reclaim resources while preserving operation, science/randomness/splits and attempt history; resume, never redispatch/reset. Without that authority/protocol preserve healthy work and wait for resources. Suspension alone proves no memory release.

## Separate authorization capabilities

Map authority to its smallest capability: `OBSERVE` reads/classifies; `PREPARE` permits bounded non-terminal materialization/reconciliation; `TRANSFER_PROTECTED_SUBJECT` the named crossing; `TERMINAL_EXECUTE` the admitted terminal effect; `ACCEPT_RESULT` project acceptance.

Bind subject/effect, authority, expiry, delegation, budget, and stop. None implies the next; access grants none. Native aliases are valid; capabilities create no V9 activation/facts.

## Resolve the consumer-active subject

Resolve state, lock, writer, and drift from production consumer/controller. Files use configured absolute path → `realpath` → device + inode → paired lock/lease → operation; other stores use native resource/namespace/generation/transaction. Path/basename/search hit/inode alone proves no active role.

Classify a hit active-authoritative, staging/materialization, evidence-only, retired, or unknown only from consumer reachability, native manifest, operation lineage, or attributable authority. Names/path labels/mtime/appearance prove none; native role equivalents are valid. Only writers/leases on same consumer-active subject conflict. Unknown freezes mutation: one resolving read supplies a STANDARD diagnostic route; otherwise stop.

## Bind envelope, topology, and concurrency

The native envelope binds closure/effects, protection, authority, budget, expiry, and stop. Guard invents no reserve. Authorized necessary edits/builds/proofs/isolated tests proceed without per-step reapproval; changed scientific, protected-transfer, deletion, or external-effect boundaries require consolidated adjustment. In-envelope capacity/partition change is reconciliation.

Approval carries only under declared identity dependencies with unchanged effects. Use a provable mutation authority—process, transaction, CRDT, queue, lease, lock, or multiwriter protocol—with ordering, collision, ownership, and terminal reconciliation.

Keep one closure owner/mutation authority for canonical/shared state and seals. Read-only validators inherit generation, envelope, budget, and stop; the owner judges. Delegated test writes require an explicitly authorized isolated envelope and grant no canonical authority. Serialize shared mutation or use native isolation.

Define topology by minimum capacity, standby/unavailable roles, concurrency, degraded form, and invalidation. Never alter or attribute dirty/concurrent user state without authority. Native state may be authority, projection, terminal evidence, or lease; derived views gain none.

## Use a DAG only if it changes the choice

Prefer an authoritative project graph. Otherwise project only three-plus dependencies, competing routes, shared gates, or an unclear critical path. Label generation/decisions and discard when stale. It is never scheduler, state, or fact source.
